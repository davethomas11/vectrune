# Vectrune 0.3.13 — Aquarium, reusable logic and new platforms

## Glowtide Aquarium and Pixel 3D

Glowtide Aquarium is a Pixel 3D game example with fish and other residents,
feeding, care, tank upgrades and saved progress. It demonstrates reusable
logic modules and composed entities, voxel scenery, audio, HUD controls and
lighting. Run it from a checkout:

```sh
vectrune examples/games/idle_aquarium/idle_aquarium.rune
vectrune test examples/games/idle_aquarium --type logic
```

The website also offers an embedded and standalone playable showcase with
shared browser saves and access to the Rune source. Its game interface is in
English.

Pixel 3D gains enhanced CPU lighting and an optional browser GPU lighting path,
with fallback to CPU if unavailable. The aquarium also demonstrates on-screen
keyboard input and expanded lighting and model behavior.

## Reusable logic and formatting

WebSocket-reactive Rune-Web pages now receive the built-in `emit` action even
when a page has its own logic. An explicitly defined `emit` action still takes
precedence. The reactivity contract example demonstrates a shared counter.
Rune Studio now opens with the VectWorms preset; saved songs remain available
from **Open song**.

Rune-Web actions can use `location.current` to request browser location, or
`location.if-granted` to use an existing grant without prompting. Both deliver
results through actions; see `examples/rune-web/location.rune` for an example.
The weather example combines device location, Open-Meteo place search and an
interactive OpenStreetMap tile map, falling back to Vancouver. Rune-Web pages
also support an `on_mount` action and a `url_encode` expression. Map and
search providers receive requests directly from the browser; see the Rune-Web
guide for privacy, attribution and tile service limits.

`@Module` provides explicitly exported actions and helpers with isolated
module state. `@Type` constructors create serializable entities with stable IDs
and methods. These features are for Rune-Web, Pixel and Pixel 3D logic, not
backend `run:` blocks; see [logic modules](../../knowledge/language/logic-modules.md)
for their scope and limitations.

`vectrune fmt` wraps long JSON collections and supported `@Logic` expressions.
Indented multiline assignments, ternaries and `if` conditions accept operators
at the start or end of continuation lines. Existing balanced collection and
call continuations remain supported. Formatting reparses and compares results
before writing; `vectrune check <file> --json` reports incomplete continuations.

## The Thirteenth Bell

The Thirteenth Bell is an example ASCII Animator platformer with GIF-backed
sprites, original music, checkpoints and a scrolling forest. It requires the
example files and a 160x48 terminal:

```sh
vectrune ascii run examples/ascii/games/clockwork/forest.rune
```

Optional desktop GIF rendering requires a source build with the
`pixel-desktop` feature. Standard release builds do not enable that feature.

## Experimental mobile and Apple TV tooling

`rune-mobile-web` packages Rune-Web frontends in Android WebView or iOS
WKWebView. `--build android|ios` produces a debug APK or unsigned iOS Simulator
app; `--export android|ios` creates an editable native project. Signing and
store distribution remain manual. The device does not include a Rust compiler
or HTTP backend. See [mobile Web](../../knowledge/runtime/mobile-web.md) for
toolchain requirements and limitations.

Experimental `vectrune tvos` commands can check, bundle, build and deploy
Pixel 3D games to Apple TV, with TV controls and save tools. Device builds
require macOS, Xcode, the appropriate Rust targets and signing setup; the
runtime source or prebuilt libraries must be available. tvOS saves use the
purgeable Caches directory. See [CLI guidance](../../knowledge/runtime/cli.md).

The mobile example directory is now `examples/rune-mobile-web`; update scripts
that previously referenced `examples/rune_mobile_web`.

## Compatibility and packaging

REST apps now show a Vectrune 404 page for unmatched requests explicitly
accepting HTML. It lists declared route templates, including authenticated
routes; set `not_found_page = false` in `@App` to disable it, or define
`@NotFound` to supply a response for all unmatched requests. Non-HTML API
requests retain the empty default 404. See `examples/beginner/not_found.rune`.
Concrete, safely linkable GET routes appear as links on the 404 page.
Append `?pretty=1` to REST route or `/openapi.json` requests to indent valid
JSON without changing response status or content type; any `pretty` value
enables it, including an empty value or `0`.
Native `respond` messages now expand `{path}` and `{pretty path}` from request
context; unknown placeholders remain unchanged and literal braces can be escaped.

The separate API emulator does not execute `@Logic` or support its new
operator continuations. Rust users of `cli::formatting::format_source` must
now handle its `Result<String, ParseError>`.

The standard release archives continue to include the `vectrune(1)` and
`vectrune-language(7)` offline manuals.
